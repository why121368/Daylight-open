# 后续实施顺序、度量与验收设计

日期：2026-10-17（北京时间）。**本文是一份后续工作及测试设计，本次没有执行其中的部署、业务测试、压测、付费调用、发信或故障注入。** 本次完成的是文档一致性检查，不构成任何云端验收证据。

本轮新增CompShare优先选型的官方资料核验；它只确认公开文档陈述，不是租户账号、地域库存、模型API或网络实连验证。平台与模型契约详见 [06](06-compshare-service-plan.md)，下面的实施门槛据此更新。

## 1. 按依赖顺序推进，而不是同时接入全部组件

| 工作包 | 具体交付物 | 前置与通过条件 | 达到的状态 |
| --- | --- | --- | --- |
| P0 需求与基线 | 首批用户/邮箱数、峰值、预算、CompShare区域/无卡创建路径、ModelVerse模型清单、外置PG网络 | 固定版本和测量方法，核验平台计费/回收及模型契约，决定CompShare计算或UHost补齐路径 | 设计输入确定，仍未部署 |
| P1 权威存储统一 | 普通邮箱/招聘/trace/sql.js/配置迁移；PG sessions、验证码原子消费；所有写路径统一事务 | 数据清单、ID与语义兼容；PG故障不落文件；迁移对账与回滚窗口 | 代码实现及隔离集成测试通过 |
| P2 可靠执行 | PG jobs、租约、邮箱有序、步骤恢复、审批/effects、SSE持久事件 | 杀Worker、重复请求、租约过期、跨路径写入及未知外部结果测试 | 可靠执行实现并有故障证据 |
| P3 角色与容器 | API/调度/I/O/OCR启动入口；固定镜像、语言包、探针、密钥注入、资源上限 | 冷启动无隐式用户数据迁移；无宿主业务目录依赖；角色分别启停不丢任务 | 容器交付通过，尚未等同云端通过 |
| P4 S1云端试点 | 首选CompShare无卡Ubuntu VM/Docker、外置PG与对象云存储、ModelVerse按量API；主机准入不满足则UHost补齐 | 通过下表平台门槛，真实云依赖/授权账号闭环、异机恢复、成本与发布回滚 | 云端单主机可恢复试点通过 |
| P5 S2多节点 | 以UCloud UK8S补齐角色Deployment/入口/节点管理，模型继续优先ModelVerse | 验证UK8S独立资源与网络，不假设CompShare实例直接入集群；多副本/节点故障/滚动/容量通过 | 多节点云端验证通过 |
| P6 有依据的优化 | HPA/KEDA、Redis、RabbitMQ、pgvector等选定项 | 每项有瓶颈、基线、对照、收益及新增故障演练 | 仅声明实际通过的优化 |
| P7 对外运营验收 | SLO与预算、值守、恢复手册、数据生命周期、租户配额、同版本证据包 | 所有承诺有负责人和可复验结果，剩余边界对用户可见 | 才能讨论明确范围的生产验收 |

P3的镜像结构和P0测量准备可与P1并行，但扩大真实流量必须等待前置条件。不能先对外部署多副本，再补会话共享、写入幂等和防重复发信。

工作包不绑定未经评估的天数。涉及现有用户数据的迁移需先备份、试迁和对账；真实发信和付费服务在后续实施任务中按授权账号、收件人和预算执行，本次方案请求不授权这些动作。

### 优云智算选型的额外准入项

| 编号 | 后续需要验证的事项 | 决策与验收结果 |
| --- | --- | --- |
| C1 计算创建 | 目标区域Ubuntu系统镜像、按量GPU首次创建、无卡8核16G启动、库存/配额/常驻条件 | 如实记录首建成本、重复重建步骤与可用时间；不能写成直接购买CPU SKU。条件不满足则UHost补齐 |
| C2 网络与入口 | 固定公网IP/源IP规则、HTTPS域名、SSE、IMAP/SMTP外联、到PG的受支持安全路径 | 不默认跨平台私网互通，不开放公网数据库作为默认方案；无法安全连通就改变应用主机位置 |
| C3 生命周期 | 重启、关机、连续关机回收规则、欠费、系统盘删除、独立盘和对象留存 | 在隔离环境证明重建不依赖原系统盘；账单/余额与回收告警可触达，所有实验设资源预算 |
| C4 存储契约 | CompShare对象云存储与US3账号/token、S3 V4、私有权限、HTTPS、Range、大小限制、孤儿清理 | 匿名/跨租户访问失败，SDK路径实测；默认无Versioning，通过不可变key与独立备份验证恢复；Pro不混作对象存储 |
| C5 模型与工具 | 逐个ModelVerse型号测JSON输出、tool_calls/tool回传、多步、取消、超时、429、usage；对照06 | 保留原动作权限；无凭据、余额不足或模型下线明确失败，不自动换服务商；任一核心契约不满足不入默认生产清单 |
| C6 向量和OCR | 独立embedding模型/维度/usage与中文召回，DeepSeek-OCR图像页质量/成本 | 解决3072/1536维差异后才切索引；图片转Markdown不冒充全PDF解析，困难页效果优于本地基线才采用 |
| C7 计费与条款 | 按量API适用范围、套餐限制、数据处理/留存/第三方模型边界、价格与实际账单 | 记录适用条款及报价日期；开发套餐不默认用于后台业务。系统usage估算与服务商账单分开对账 |
| C8 恢复与承诺 | 计算/模型/存储同账号故障、外置PG恢复、模型供应商不可用、服务约定 | 实测与系统SLO分开；核验CompShare公开条款与订单适用范围，不继承其他UCloud产品SLA |

准入项不得仅凭官网“支持OpenAI”“免费带宽”“持久存储”等概括判通过。官方明确能力、账号实际可用、代码适配成功、故障恢复通过分别记录；未达到门槛时保留优云智算适合的服务，只为有具体缺口的层选择补充方案。

## 2. 测什么，以及如何证明

| 层次 | 测试内容 | 关键断言与证据 |
| --- | --- | --- |
| 业务回归 | 日程创建/取消/改期、失败邮件重试、工作台确认、人工回执、助手/招聘/发票入口 | 取消保留、双向关联、示例隔离、原ID和权限不变；现有npm测试按改动范围运行 |
| 真实基础设施集成 | 真PG事务、US3读写删除、生产会话、部署入口、TLS与CA | 配置保存≠连接成功；事务失败无半提交；对象鉴权、版本和恢复可验证 |
| 多进程与多副本 | 同邮箱两次同步、手动修改与模型提交竞争、重复审批、两用户请求同ID | 约束可证明唯一结果、旧版本拒绝、越权无读取/动作；不是只断言HTTP200 |
| 任务故障 | 领取后退出、心跳中断、提交前后退出、重启、迟到Worker、SSE切副本 | 不丢可恢复任务、旧fence不提交、已完成不重做、进度/结果可重连 |
| 外部副作用 | SMTP认证失败、DATA超时、部分接受、回执保存失败、会议返回未知 | 明确未发才允许重新审核，unknown不自动重发；远端接受与送达分别记录 |
| 依赖故障 | PG断连/主备切换、US3超时、模型429/5xx、可选Redis/MQ故障 | 无本地权威回退，错误可见、退避有界；外部故障不被伸缩放大 |
| 权限与恶意输入 | 跨用户/邮箱/工作台、伪造job、恶意邮件指令、任意模型URL、附件解析炸弹 | 工具权限由服务端检查；限制内网/元数据外联；不泄露正文/凭据；有限资源内失败 |
| 发布与恢复 | 新旧角色共存、schema扩展、回滚、节点丢失、PG/PITR、对象对账 | 旧任务可处理或明确拒绝，已发送事实不复活；按故障范围测RTO/RPO |
| 容量与质量 | 平稳/突发/积压、OCR大页、RAG多片段、模型质量、扩缩容 | 给出负载/成功率/延迟/资源/费用分布，失败和未知费用不从报告中消失 |

真实SMTP测试只向明确允许的测试收件人发送；以测试服务器模拟DATA断连等危险窗口，少量受控真实调用验证协议。模拟故障结果与真实云依赖结果分开编号，不能混为真实邮件闭环通过。

## 3. 工作负载与性能测量计划

采用 [04](04-deployment-and-capacity.md) 的100个活跃邮箱、每天每邮箱30封新邮件作为**讨论用假设**，不是现有用户规模。试验至少覆盖小样本、代表性目标样本和过载样本；真实环境预算不足时，模拟到达流和真实依赖限额分开测试并说明边界。

| 测量组 | 起步试验设计（待执行） | 为什么需要 |
| --- | --- | --- |
| 只测API/存储 | 5/20/50请求每秒分档，读写混合与只读分开；预热后每档至少15分钟，重复3次 | 找出PG/会话/查询瓶颈，不被模型等待掩盖 |
| 交互长连接 | 10/50/100个SSE连接，逐级增加，记录活跃任务与闲置连接比例 | SSE占连接与内存但未必高CPU，验证入口和Pod伸缩指标 |
| 邮件任务 | 100邮箱分时到达3,000封/日等效流；另注入300封/5分钟、分布于20邮箱的过载突发 | 额定负载测排队SLO，过载测准入/公平/恢复；短时实验需注明加速比例 |
| 单邮箱热点 | 同邮箱多封通知、取消与改期；同时进行手动修改 | 验证有序处理和版本冲突，而不是只看总吞吐 |
| OCR | 文本PDF与扫描件分开，1/10/50页阶梯；逐档限制字节与最大解析时间 | 页数、分辨率和语言包影响内存，文件个数不是足够的容量指标 |
| RAG | 每邮箱1千/1万/10万chunk试验阶梯，固定中文问题与引用答案集 | 判断扫描/向量索引必要性；过大的阶梯可先离线测，不无界消耗线上资源 |
| 持续运行 | 代表性任务与过期清理连续24小时，再以更长观察窗复验 | 发现内存增长、连接泄漏、PG膨胀与积压；15分钟压测不能证明运营可靠性 |
| 自动伸缩 | 同负载固定副本对照，之后启用扩缩容并在峰后回落 | 证明排队改善、没有更多429/重复动作、空闲成本确实下降 |

压力生成工具可选k6：适合HTTP/并发用户与结果导出；若某SSE能力在选定版本不合适，使用有界Node压测客户端补齐。PG与任务侧指标由采集器记录。无需为了测试再搭建大型性能平台。

上面的300封/5分钟不是承诺在60秒内排完的额定负载。若沿用04中每封一次调用、全局有效额度24次/分钟的算例，其到达率60次/分钟已超过供给。忽略启动与执行波动，持续5分钟可积压约180次调用，之后完全无新到达也还需约7.5分钟消化。此组验收的是有界排队/明确拒绝、租户公平、无重复效果和可解释的恢复时间；正常队列SLO只能在明确的额定到达率、突发包络与额度内验收。不能靠扩Pod绕过配额，也不能把过载样本删掉伪装整体达标。

容量估算用 `L = λ × W` 检查平均在途量，`λ`为到达率、`W`为实测平均执行时间；初始并发可按 `λ_peak × W / 目标利用率`估算，随后受模型RPM/TPM、邮箱连接、PG与CPU限制。p95服务时间用于尾延迟风险分析，不能随意代替均值套用Little定律后称作实测吞吐。多阶段任务按阶段与任务种类分别统计，冷OCR/热缓存不可混在一个平均数里。

## 4. 指标口径与候选验收目标

以下数字是**待P0固定的起步目标**，与04一致，未宣称已达标。

| 维度 | 候选目标/必需口径 |
| --- | --- |
| 短API | 指定同地域网络、目标读负载下，读API p95≤500ms；5xx<1%，同时报告鉴权失败、限流与业务冲突比例 |
| 可运行队列 | 约定额定负载、突发包络及外部额度内，入可运行状态到首次成功领取的p95≤60秒；过载恢复单列，另报最老可运行年龄和每租户分布 |
| 全任务耗时 | 从接受任务到最终状态，拆分排队、依赖等待、IMAP、OCR、模型、写库；报告p50/p95及失败/超时，不预填已达目标 |
| 等待与未知 | waiting_approval、配额等待、业务依赖阻塞、unknown数量与年龄单独展示；不能为满足队列目标而将积压随意改名“等待” |
| 正确性 | 测试集跨租户泄漏为0；PG完好的进程/应用节点故障中已提交业务丢失为0；相同意图重复外发及unknown自动重发为0。数据库恢复按约定RPO测损失窗口，窗口外数据不得丢失，窗口内外部动作须隔离核验；有限样本零缺陷不等于数学上无故障 |
| 质量 | 日程/截止日期提取正确率、取消改期目标匹配率、引用正确率、人工修正率与漏报率；与人工基线及原版本对照 |
| 可用性 | P0明确服务时间和用户关键请求，再约定月度SLO；短压测5xx比例不能替代月度可用性或云产品SLA |
| 恢复 | 使用04按应用节点、数据库、地域分别定义的RTO/RPO；外部已发生效果独立核验 |
| 成本 | 每封成功新邮件、每份成功OCR文档、每个完成工作流费用；固定成本分摊、重试、未知usage和人工核验另列 |

模型429不能简单从成功率统计中删除。可以单列供应商错误与本系统错误帮助诊断，但用户感受到的完成率、全任务时间仍需包含其影响。人工审核等待可从“机器执行SLO”中拆开，却要保留在完整业务周期指标中。

## 5. 如何用对照验证技术选择

| 决策 | 对照实验 | 保留或改变决定的依据 |
| --- | --- | --- |
| OCR独立进程 | 同负载下比较共进程与隔离进程API延迟、RSS和任务完成率 | 隔离应保护API且不引入超出预算的资源成本 |
| PG jobs | 空闲轮询/突发任务下测业务p95、DB CPU/I/O、WAL、池等待、领取延迟 | 优化索引/批次/清理仍超目标才比较MQ；不是指定某个邮箱数就必须切换 |
| RabbitMQ候选 | 同一持久job语义，PG直接领取与outbox+MQ传输对照 | 加入broker后的吞吐/隔离收益要覆盖账单、运维和故障复杂度 |
| Redis候选 | PG会话/限流写负载与Redis实现对照，测命中率、撤销延迟和故障行为 | 先证明热点；任何性能收益都不能牺牲撤销、验证码一次性和预算约束 |
| K8s | 容器同构负载下，固定单机/多节点运行的发布停机、节点恢复和总成本 | 若需要的故障冗余与发布目标只有多节点满足，则接受固定成本；否则S1继续验证 |
| HPA/KEDA | 固定副本与动态副本的排队尾延迟、扩容时间、429、成本对照 | 扩容有效且收缩安全才启用，额度瓶颈时先背压 |
| pgvector | 相同权限过滤和中文评测集：关键词/精确混合/ANN检索 | 质量不退化、隔离无漏洞、延迟和数据库资源收益明确后切换 |
| 上下文裁剪/便宜模型 | 同一数据集、同一工作流比较正确率、人工修正、Token与成本 | 不能用更低账单掩盖漏掉截止日、错发或更多人工修正 |
| CompShare计算 | 无卡Ubuntu VM与UHost补充方案比较首次创建/重建时长、PG连通、常驻资源、月总成本和回收风险 | 优先CompShare满足门槛的方案；无需GPU不能把GPU持续运行费隐藏于“算力平台优势”中 |
| ModelVerse按量API | 平台内候选模型与已授权现有服务做同样本对照，包含结构化失败、工具错误和所有重试 | 优先采用达到质量/权限/预算要求的ModelVerse型号；保留不足项，不用套餐次数或官网价格替代真实usage/账单 |

所有对照固定业务版本、数据规模与模型配置；一次只改主要变量。实验失败也是证据，写出瓶颈和下一步，不删除失败样本后重新定义“成功任务”。

## 6. 安全、生命周期与运营验收

- **权限：**API、Worker、检索、附件、SSE和后台回放全链路按用户/邮箱检查；审批过期、撤权与删除邮箱后阻止尚未执行的动作。管理员查看与导出有审计，不能直接把普通业务日志当管理员授权来源。
- **外联：**测试用户自定义模型/IMAP/SMTP/CalDAV端点、重定向、DNS解析与IPv6；拦截私网和云元数据访问，学校私网连接走显式批准的隔离方案。TLS证书错误不能通过关闭校验“修好”。
- **数据生命周期：**区分原邮件、附件、派生OCR/索引、任务事件、发送证据、备份的保留期。删除请求先撤访问，再可审计地清理派生数据，明确备份到期时间；不能为了删进度日志丢掉防重发证据。
- **预算与公平：**每用户/邮箱/模型凭据有任务、Token、附件页数/体积及发送额度；过载时拒绝或排队并显示原因。活跃大用户不能让其他用户无限等待。
