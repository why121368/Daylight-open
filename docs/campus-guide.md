# 校园生活：使用方式、功能对照与数据验收

更新日期：2026-11-02。

Daylight 新增公开入口 `/campus`，把地点、步行路线、活动、课表、餐饮和交流接入现有账号与日历。原来的科大学习站仍在 `/app/campus`，邮箱和招聘工作区仍通过 `/app` 使用。

参考项目是用户图片二维码指向的 [上科大一图通](https://map.niyiwei.com/)。对照基于其公开页面、公开前端和当时可读的数据接口；需要登录或管理口令的行为未在参考站提交验证。Daylight 独立实现对应能力，没有将参考站代码、校园底图、菜单库、照片或街景复制为产品资产。下表同时记录已经实现的能力和仍有差异的部分。

## 本轮新增（2026-11-02）

新增手机地面导航接力、可选高德站内步行路线、本人上科大邮箱日程与活动自动投影、三食堂六档口的本周菜单，以及校园小 D 助手。2026-11-03 增加默认本人模型、能力引导、自习空档、活动冲突筛选与多步工具查询，已发布公网；使用步骤、菜单来源、持久迁入、模型行为与实际验证边界见 [校园功能说明](campus-life-2026-11-02.md)、[助手发布记录](campus-assistant-public-2026-11-03.md) 与 [STATUS](../STATUS.md)。下表历史底层能力中地下道路与车辆维护仍保留，主校园页仅提供地面步行。

## 当前数据与验证范围

**普通运行的新目录已接入用户指定的 [学校官方校园地图](https://map.shanghaitech.edu.cn/)。** 2026-10-28 读取公开接口与地图瓦片，导入 65 个建筑区域/轮廓及 44 条校园服务记录，共 109 个可搜索地点，并提供本地底图快照。原 BD-09 坐标已转换为 WGS84，底图按 Web Mercator 重投影。部分原始记录更新于 2018 年；服务可能沿用关联建筑中心，入口、开放时间、通行状态仍待核对。没有把官方地图的建筑轮廓推断成步行路网，也未复制第三方“一图通”的数据。

**`npm run demo` 的隔离演示仍提供原创示意目录。** 包括 9 个示意地点、地面/地下示意道路、3 场示例活动、2 个示例餐饮区域、3 个示例菜品、1 份示意楼层图及 1 份示意货架图。这些示例不用于实地导航、取件或参加活动。普通目录已接入本周用户提供菜单；公开活动、楼内图、货架及街景需管理员另外导入；完整资料清单与现场流程见 [校园 Demo 资料清单](campus-demo-data-checklist.md)。

街景与卫星图源初始为空；社区帖子、评论、评分、排队反馈、活动来源配置、待审核草案和签到初始为空。用户自己的资料由实际保存行为产生。配置字段已保存、来源成功读取、模型返回结果与云端验收是不同状态。

地点英文名、入驻单位、活动英文标题、英文摘要/详情及主讲人等内容字段已支持；当前界面以中文为主，尚未覆盖完整中英文 UI 切换。学校地图快照保留来源、抓取时间和图片校验和，公开运营前需确认学校地图使用许可；其他菜单、楼内图与照片同样需维护者核验来源与时效。

公开部署及二维码的操作见 [公网访问说明](public-access.md)。二维码编码网页地址；本地地址生成的二维码仍是本地预览，域名格式通过检查也不表示手机已能连接。

## 从本地开始使用

1. 按根目录 README 安装依赖并运行 `npm run dev`，打开 `http://127.0.0.1:3000/campus`。具体端口以服务启动输出为准。
2. 普通目录在“地图”搜索“教学中心 / 图书馆 / 丝路餐厅”，查看学校底图、建筑轮廓、点位来源，并可收藏和分享。图层提供“上科大地图 / 位置示意 / 地理底图”。已有目录由管理员点击“维护 → 目录 → 导入上科大地图”增量补入；不会覆盖已有同编号地点。隔离演示可搜“教学中心 101”查看示意一楼，使用 `A-3-2045` 体验示例货架；普通目录需先提供真实楼内图和货架信息。
3. 地图选择终点后打开腾讯步行导航；站内可使用已核验路网或可选高德服务端 Key，未配置时不绘制虚构路线。主页面仅提供地面步行；模拟行走不申请定位。目录收录街景后，可前后/拖动或点击小图切图；最后一张可手动完成预览并返回地图，不判断现场到达。底层地下车辆候选能力不能用于实际驾驶。
4. 需要真实定位时主动点击地图定位按钮，浏览器还会询问权限。用 HTTPS 或本机地址访问；示例目录与实际位置无关，不能据此导航。GPS 信息可能发送给本站路线接口用于规划，不进入默认分享链接。
5. “我的”填写常用地点、手动课程或截图识别；截图提交前核对所配置模型与费用，识别后逐行确认。游客资料保存在当前浏览器；登录后可主动合并到账号。使用不同账号应分别检查资料隔离。
6. 登录并绑定上科大邮箱、配置模型后，后台提取的有效邮件安排自动显示在“日程”和“活动”的私人区域，每分钟刷新并跟随取消/改期。 “日程”选择日期，添加安排、查看冲突/路线/建议，导出当天 ICS；账号还可将安排写入 Daylight 当前邮箱日历，或从自己的邮箱/学习站日历选择安排加入校园行程。时间更新保留取消/替换历史；再次相同导入保持幂等。
7. “活动”筛选通知、查看已收录的中英文介绍、原文与正式报名链接、添加参加意向；展开时光机体验回放。签到需活动主办方提供当前有效码，不能靠点击活动自行证明到场。
8. “美食”选择日期、餐次，再筛选预算和口味，查看窗口与反馈时间。游客也可反馈当前食堂或窗口排队，评分和售罄反馈需登录；没有有效反馈时明确显示“时段估算”，不能据此当作现场人数或实测等待。
9. “交流”可匿名浏览，登录后再发图文、评论和互动。AI 总结会将所选公开笔记与评论提交给用户配置的模型；先在弹窗确认提交内容。
10. 右上角“扫码分享”用于查看/复制/下载当前链接。完成公网部署后从真实 HTTPS 域名重新生成，使用手机移动网络与另一台设备试扫。

### 地图标注与密集地点

- 默认开启“智能地点标注”，根据屏幕像素空间、缩放和地点优先级排列名称；选中地点和有活动的地点优先。平移、缩放及容器尺寸变化后重新排列，避免名称之间、名称与图标/控件之间重叠。
- 普通点位使用小圆标；距离过近的点位合并显示地点数量，点击打开附近地点列表。列表可打开单个地点、展开既有楼群，学校地图和地理底图还可“放大此区域”。位置完全相同的记录保留在列表中，不通过修改真实坐标分开。
- 常驻名称限制宽度，校门省略重复学校名称及地址；悬停、键盘聚焦和选中时可查看全名。图层面板可关闭智能标注，选中地点仍显示全名。名称密度变化只影响展示，搜索、详情、分类、来源和分享继续使用原始地点数据。

## 把真实校园资料放入系统

### 1. 确定来源与坐标

收集可使用的校园地点、步行道路、轮廓、入口、楼层图、货架、活动和菜单；保存来源链接、授权范围、勘测日期和维护责任人。Daylight 的地理瓦片/GPS按纬度经度使用；参考站 BD-09 数据不能原样当 WGS84。使用其他坐标系的数据时，先按合法授权完成转换与现场校准，不在导入时凭外观猜坐标。

所有真实道路应核对长度、方向、开放情况、地面/地下、遮雨、步行许可及台阶/电梯/坡道。建筑点或入口关联节点不等于周围都能直线穿过；目录坐标与通行资料需要共同维护。

### 2. 建立管理员和恢复点

按 [公网访问说明](public-access.md) 或现有部署文档创建管理员，再用该账号进入“维护”。先导出当前公共目录，并按部署备份流程保全数据库及附件。不要将真实账号口令、IMAP 授权码、API Key、私人邮件正文放入目录 JSON。

“清除示例”与“导入目录”有各自确认预览。完整目录导入会替换该公共目录版本；先核对记录数量和关联关系，不能当作无条件增量合并。其他管理员已更新时会拒绝旧版本，刷新并重新核对后再保存。

### 3. 维护地点、道路与图像

先用“目录”创建节点、地点、道路等基础资料，再用“地图编辑”描轮廓、入口和连线。新增道路的几何长度只是初始草稿估算，拖动节点后不会自动证明长度准确，应重新核对实测距离。入口可按阈值投影到最近轮廓边，无轮廓或超阈值时保留点击位置并提示；其路网关联使用明确选中的节点，或在“入口批量绑定”中预览距离匹配后应用。绑定不证明入口到路网之间可以直线通行。

需要刷新后继续编辑时，管理员可显式点击“保存本机草稿”。草稿按账号与公共目录版本隔离存入当前浏览器 localStorage，只保存几何字段（地点的节点关联/轮廓/入口、节点、道路、街景），不含活动或餐饮内部备注、账号凭据，也不保存尚未闭合的轮廓点。刷新后可选择恢复或丢弃；同版本经确认恢复后仍是未发布修改，且可撤销回公共基线。旧版本只允许导出或丢弃，应载入最新目录后重新核对，不能静默覆盖。未点击本机保存的修改只在内存；离开提醒不等于自动保存，切换维护栏目也不会自动保存。浏览器清理、禁用存储或容量不足会影响本机草稿；保存报错时应导出备份。本机草稿不加密、不跨设备，也不等于服务器保存。

发布前会读取最新管理员目录，将几何修改合入后按版本检查写入，保留隐藏活动和内部备注。公共版本变化时暂停发布并保留本机草稿，维护者需重新载入和核对。

连接道路默认把同层几何交点与 T 形交点切成共享路口，保留长度比例、方向和街景里程关联；不同层不自动连接。重叠路段和无法发布的过短切段会提示处理。勾选的自动连通仍需现场核对，关闭道路或没有交叉通行条件的路口不能只凭画线确认。删中间点工具仅合并近乎共线、同属性的两条边，保留总里程、方向与路段街景；转弯、有其他连接或仍被地点/入口/节点街景引用时拒绝。

“街景按里程插值”可以选择本机图片批量上传，或填写每行 `01-scene.jpg | https://授权图片地址` 的清单。每批 1–50 张 PNG/JPEG/WebP，单张不超过 20 MiB；文件名开头数字优先排序，兼容 `scene-01.jpg` 等结尾数字，序号均为 1–50。逐个上传可看到成功/失败并单独重试，不复用社区私有配图。上传只保存独立的 `campus-media` 素材；仍需按路径顺序选择连续路段，预览数字顺序、沿路里程、坐标和重复项，加入草稿后显式保存目录。图片 URL、原文件名和来源一起保存，重复导入同图同位置会跳过。

未被公共目录引用的上传素材仅管理员可读；公共目录投影引用后才允许匿名读取，移除引用或隐藏唯一引用活动后会撤销匿名读取。公开前应确认图片授权和画面中不含私人信息。外部图片保持 HTTPS；本地 HTTP 开发只接受明确同源、路径精确为 `/api/campus-guide/media/<UUID>` 且不含凭据/查询参数/片段的已上传图片。该操作按录入里程等距推算，不包含现场采集或视觉定位；路线预览会按实际行进方向排序这些图像。切图时同步路线小图与图片记录点，点击小图序号也可切图；没有坐标、节点或道路里程的旧图片只展示图片，不编造精确点。手动完成预览只表示结束看图，最后一张未覆盖到路网终点时仍展示剩余目录里程，可返回原地图或车辆候选图。

除随项目部署的校园底图可使用受限的 `/campus-maps/` 同源路径外，其他目录图片字段保存绝对 URL，上传素材也记录当时本站的 origin（协议、域名和端口）。应在最终 HTTPS 域名下上传对外素材；本机地址或旧域名链接不会随部署自动改写。更换域名时，保持原素材地址可访问，或从新域名重新上传并替换目录引用；仅修改链接中的域名不足以迁移原素材的公开引用记录。迁移前保全数据库和附件。

运行“路网诊断”，处理孤立节点、地点未连接和无障碍标记；对诊断候选逐项现场确认。地面/地下与单向道路还应分别规划典型路线，检查不会穿墙、穿过封闭道路或让无障碍用户走楼梯。

在“公开信息”填写目录来源、说明、中心和地图署名。卫星需同时提供有授权的图源 URL 和署名；外部地图的许可、请求量与供应商费用独立核对。楼层/街景记录使用维护者提供的授权图片链接或管理员上传的独立素材；无图片明确显示空态。不能把参考站或搜索引擎上的可见图片直接当作授权资产。

### 4. 活动来源先审后发

- 添加公开 HTTPS JSON、RSS/Atom、ICS 或官网 HTML 地址，可先保持“仅手动同步”；手动执行后检查运行记录和草案数量，再决定是否启用定时。地址不能含私人 token，服务会限制目标地址、跳转、时长与响应大小。
- JSON 可提供最多 500 项活动数组或 `{"events":[...]}`；稳定来源标识用于去重。活动需要可核对的标题、带时区开始/结束和目录地点。缺失信息会保留在待审区，不自动发布。
- RSS/Atom 只读取可识别字段；发布时间不是活动开始。ICS 只处理基本 VEVENT，支持 UTC 或明确的上海时区，未实现 RRULE 展开与完整全天事件导入。遇到此类来源应先提供规范化 JSON，或人工核对录入。
- 官网 HTML 优先读取该单页的 `application/ld+json` 活动数据。没有结构化活动时，仅提取同站活动列表链接作为缺时间/地点的待补全草案；不执行网页脚本，不自动打开详情链接，也不会从标题猜日期。学校动态页面、登录页或其他格式可先人工整理成 JSON。
- “本人已入库邮箱”来源从当前管理员自己的邮箱中选择，设置最近邮件数量与关键词后可手动或定时扫描已入库快照；草案和来源配置仅本人可见。需要新邮件时先通过原 Daylight 邮箱同步入库，此功能不建立额外 IMAP 连接。勾选启用代表允许按这些规则建私有草案，公开仍需逐项审核。
- 邮件来源使用“选择已入库邮件”，仅列出当前管理员自有资料。点击一封建立私有审核稿，去除私人联系信息和邮件往来，再补时间/地点/原文。该过程不把个人邮箱整体公开，也不等同于新的 IMAP 自动采集器。
- 审核页保存草案仍为私有；勾选核对声明并确认发布后才进入游客目录。相同内容不重复入队；来源发生变化再次待审，原公开活动保持原样。拒绝某份草案不删除已发布活动。

定时执行使用现有 Scheduler；每次受限读取管理员启用的公开来源或以所有者身份读取其自有邮箱快照，并记录运行身份、租约、结果及失败退避。部署后需实际启动 Scheduler 并核对运行记录，“开启定时”仅是已保存的偏好。

### 5. 菜单、货架和互动

食堂、窗口、营业时段、临时停业与停止接单、菜品、规格/计价单位、待定价格、参考价、供应日期/星期/餐次、售罄与菜单原图由维护者录入；用户评分和售罄反馈是参考。匿名和登录访客可反馈食堂/窗口排队，30 分钟过期，未有反馈时的高斯餐峰估算始终标明“时段估算”。管理员概览的 24 小时排队统计只计成功接收的每次提交，包含同一访客获准更新，不把它当作独立人数；失败或限流不计。界面会显示尚未开始、未满 24 小时或覆盖完整窗口，以及统计起点和总量/档位/餐厅分布。旧的当前反馈不回填历史，刷新也不补造提交。真实货架图必须登记准确的前缀/别名、层数和设施位置；取件码只做本机匹配，不能替代工作人员核实。

社区图片存入现有附件存储；公开帖子引用后才向访客展示。隐藏/删除与图片读取权限应一起验收。目录 JSON 导出不含这些附件与评论，恢复演练需同时覆盖它们。

### 6. 清理示例并试运行

在保留恢复点后清理示例，检查真实记录不会依赖示例地点/节点。核对 `isDemo` 与目录说明，只有资料完成授权和现场核验后才取消示例标记。先邀请少量用户试用，记录路线错误、误报、延迟和成本；不以界面看起来完整作为校园实测通过的依据。
