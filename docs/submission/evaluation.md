# 基础邮件提取评测

`evaluation-cases.json` 是 15 封人工编写的固定合成邮件，覆盖保研面试、全天与多日活动、相对日期、材料截止、已有待办合并、取消、时间与地点调整、模糊目标、普通资讯和邮件内不可信指令。每封有独立的已有日程/待办上下文及人工 golden。样本正文均为合成内容，不含真实邮箱或个人信息。

这套工具只评价 **生产 `extractEvents` 调用真实模型，再用生产 `importEmail` 在内存应用结果**。它不连接 IMAP/SMTP，不发信，不评价工作台关联/人工确认完整流程，不代表用户群体准确率、提示注入安全保证或云端容量验收。样本少且措辞明确，属于可复现回归集；不得据此宣称通用准确率。执行时采用仓库默认提取提示词，而非用户保存的定制提示词。

## 零网络检查

```powershell
node scripts/evaluate-mail.js --validate
node --test server/mail-evaluation.test.js
```

无参数等价于 `--validate`，只检查数据结构，`model_calls` 固定为 0；不会导入生产服务或读取真实设置。测试使用纯评分器和内存模拟模型响应，不能写成“真实模型通过”。

## 真实模型小批量运行

使用 Node.js 22 或以上，在项目根目录运行。`--live`、`--settings` 和 `--limit` 都必须显式提供，最多每例一次请求，不自动重试。先用 1–3 例核对连通性、用量和单价，再决定是否跑剩余例；本工具不采购服务，也不提供固定费用上限，调用前需按账户实际价格与余额控制预算。

```powershell
node scripts/evaluate-mail.js --live --settings data/settings.json --limit 3
node scripts/evaluate-mail.js --live --settings data/settings.json --limit 3 --cases cancel-interview,ambiguous-cancel,invitation-with-injection
```

设置文件只读取六个白名单字段：`baseUrl`、`apiKey`、`model`、`tokenPriceIn`、`tokenPriceOut`、`tokenPriceCachedIn`。三项价格单位是人民币元/百万 Token，缺失时对应费用保持未知。若模型保存在 `userPrefs` 中，增加 `--settings-user <用户ID>`；选中用户字段优先，缺失字段取根配置。不要把含密钥的命令、设置内容或截图加入提交材料。URL 必须无内嵌用户名、密码、query 或 fragment。

每次运行强制新建 `work/mail-evaluation-*/isolated-data`，在动态导入生产模块**之前**替换 `DAYLIGHT_DATA_DIR`。不会把整个用户设置复制到隔离目录，不启动 API、队列、调度、邮箱或数据库。模型凭据只留内存；正文、摘要、完整模型输出和提示词均不写入结果。实际结果只导出动作类型、已知目标 ID、有效时间、数量、预设标题关键词命中和地点匹配布尔值。默认关闭自动本地代理探测，显式代理环境变量仍按生产请求逻辑使用；证据只记录是否存在代理，不记录代理地址或凭据。

输出文件：

- `manifest.json`：Git SHA/dirty、数据集与服务端/共享 JS/工具/依赖锁文件 SHA-256、运行环境、请求中的模型名、端点 origin、单价快照、选择的案例和请求上限。请求名称不能证明中转服务底层模型身份，`model_identity_verified` 为 false。
- `results.jsonl`：每例请求前同步写入 `case_started`，结束后写入 `case_result` 并刷新磁盘，包括 expected、受限 actual、断言、失败类别、耗时、Token/费用和客户端进程资源。只出现 started 而没有 result 的例表示中断或结果未知，不能删去后重算成功率。
- `summary.json`：计划/完成/通过/失败/未完成例数，成功率分母始终是本次选定计划数；失败例保留在延迟样本中；p50/p95 使用 nearest-rank，并显示样本数。15 例及更小样本的 p95 等于最大观测耗时，不能据此预测稳定尾延迟。费用显示已知小计、计价覆盖率和未知用量数量；缺失费用不会按 0 算。全部已完成且全部可计价时才给出总费用。每次更新复算已登记源文件和数据集散列，标明运行中是否变化。

动作按无序的一对一人工 golden 匹配，检查目标、精确时刻、全天标记、材料期限、继承地点和必要标题关键词；同时检查模型原始动作/待办数量及内存最终状态，避免空输出或被下游过滤的错误操作假通过。取消保留原事件，改期保留取消旧事件与新事件；模糊目标必须保留原事件并进入人工匹配。待办合并必须命中既有 ID，不能只判断生成了文字。

资源数字是**评测客户端 Node 进程**（含内存解析和应用），RSS 每 50ms 采样、CPU 为进程累计时间差；它们既不是模型服务端资源，也不是部署应用服务器资源。单例耗时包含生产模型请求、解析和内存应用，不含 IMAP、SMTP或人工等待。模型请求中的当前时刻仍为真实运行时刻；邮件日期固定，相对日期以邮件时间为准。每例单次调用上限为生产默认的 60 秒。

Ctrl+C/SIGTERM 后不再开始下一例，等待当前调用完成或超时再保存摘要。强制终止可能没有最终摘要，应结合 `case_started` 重建未完成分母并保留原始文件。摘要会在每例结束时更新。每次重跑创建新目录，不能覆盖失败样本；挑选案例的运行须披露 `selected_cases`，不能作为全量结果。

提交时应冻结代码 Commit，将本次 `manifest.json`、完整 JSONL、summary 和本数据集作为同一证据包保存；原始文件先检查，允许有失败与未知。不同模型/提示词/版本的结果分别报告。费用来自实际返回 usage × 本次配置单价，不代表服务商账单核对；发生响应丢失时，未知调用仍可能计费。
