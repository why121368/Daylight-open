## 已导入的地图资料

来源为用户指定的 [上海科技大学校园地图](https://map.shanghaitech.edu.cn/)。本次实际读取公开查询接口与校园地图瓦片，整理为随项目部署的快照：

- 65 个建筑区域与轮廓、44 条校园服务记录，共 109 个可搜索地点；包含图书馆、教学中心、学院、公寓、餐厅、校门及服务设施。
- 学校绘制的校园底图，已转换坐标并保存在本站；查看“上科大地图”无需实时访问原站或填写百度 Key。
- BD-09 转 WGS84；底图按 Web Mercator 重投影，与已转换的地点、轮廓及浏览器 GPS 使用相同基准。该转换没有现场精度验收。
- 地点保留来源链接；底图保留学校署名、抓取时间与 SHA-256。原始公开记录含 2018 年更新日期，抓取时间不能当成校方最新核验时间。

服务记录可能与同名建筑重合；缺少独立坐标的服务使用原站关联建筑的中心，并明确标注。建筑中心不代表入口。没有将来源的人员标识、账号字段、第三方 Key 或前端代码放进公开目录。

**当前可以演示：** 打开学校地图、缩放拖动、搜索真实地点、分类筛选、查看轮廓与来源、收藏、设为住处/实验室、分享地点。路网、活动、菜单、室内图、货架和街景尚未从该网站导入。普通运行的新目录提供学校地图；`npm run demo` 仍提供明确标注的原创示例，用于离线体验所有原有流程。

## 交付格式

1. **公共资料：**优先整理成目录 JSON。管理员“维护 → 目录 → 导出目录”可获得当前字段样板；图结构、字段与引用会在导入预览时校验。普通 JSON 导入会替换整个公共目录，先导出备份。
2. **地图快照：**老目录可点击“维护 → 目录 → 导入上科大地图”，只补入缺少的学校地点与地图元信息，保留已有同编号地点、其他目录及个人引用。并发修改会因版本不一致被拒绝。
3. **图片：**提供自有/授权 PNG、JPEG、WebP；街景可在“地图编辑”批量上传。楼层图和菜单图可填写可访问的授权图片地址。学校底图的公开运营许可仍需维护者确认。
4. **课表：**准备截图或按“我的”表单逐条录入；学期、周次和当天日期须一致。活动和安排统一使用北京时间，全天结束为最后一天的次日零点。
5. **通知源：**提供具体活动列表/RSS/ICS/JSON 链接，或本人已入库邮件；抓取先入待审核区。只给学校主页通常不足以获得完整活动时间和地点。

### 地图资产与存储命令

```powershell
# 离线校验随项目提供的地点 JSON、底图和校验和
npm run campus:import:shanghaitech -- --check

# 明确从学校公开服务重新抓取、转换并更新随项目部署的快照
# 该步骤联网，但不写当前运行目录；完成后需重新构建、部署前端。
npm run campus:import:shanghaitech
npm run build

# 已有 Windows 生产配置：先预览将导入的数量与存储模式
npm run campus:apply:shanghaitech -- --environment-file data/runtime/environment.json

# 保存备份后，按目录版本增量写入配置的 PostgreSQL
npm run campus:apply:shanghaitech -- --environment-file data/runtime/environment.json --apply
```

无环境文件时，应用命令使用环境变量的数据库/数据目录；明确的生产模式缺少数据库会失败。首次未保存的目录直接写入学校地图，已有目录增量补充并保留人工修订。备份写在选定数据目录的 `campus-guide/backups/`；不是全系统备份。

## 建议现场流程（约 6–8 分钟）

1. 打开校园地图，搜“教学中心 / 图书馆”，查看学校底图、地点轮廓和来源；分享一个地点。
2. 打开已准备的个人课表，展示当天安排和常用地点。
3. 选择寝室至教室，查看已核验的步行路线和出发时间；有真实属性时再比较避雨或无障碍路线。
4. 找到课后讲座，检查正式报名入口，加入个人日程；展示与原课程冲突的提示。
5. 选择“15 元以内”的用餐候选，核对菜单来源/有效期；现场提交一次排队反馈。
6. 查看一层教室图或一段路线实景；用演示取件码定位货架。
7. 在关联活动的交流区查看评论，演示收藏；已配置并授权模型时再生成摘要。
8. 管理员从一封通知建立私有草案，核对时间与地点后发布；展示个人日历互通、来源和版本保护。

每一步须使用已经准备且当前有效的数据。示例回放、真实学校公开数据、真实模型/邮箱实连、目标公网验收应分别说明。
