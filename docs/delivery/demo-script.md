# Daylight 现场演示脚本

建议时间：5–8 分钟。使用 `npm run demo` 启动，浏览器打开 http://127.0.0.1:3180/login。所有展示人员均能看到「隔离演示 · 预置结果」标记。账号与安装说明见 [交付入口](README.md)。

## 0:00–0:40：说明问题与进入工作区

讲解：「通知读过以后，还需要变成具体安排、材料和下一步。Daylight 把来源、执行过程和结果放在一起。」点击「进入演示工作区」。总览已有样例，直接进入邮件页，无需先配置邮箱和模型。

说明：「这里是预置结果，演示进程屏蔽了外部调用。真实邮件流程使用同一套日程、待办和记录模块；真实服务的验证按版本另外记录。」

## 0:40–2:00：邮件、改期、冲突和幂等

1. 在「邮件」找到「Daylight 产品设计评审」及「调整」邮件。打开关联日程，展示原时间取消、新时间有效以及变更来源。
2. 找到「取消｜和陈可喝咖啡」，说明取消保留原安排，避免丢失来源。
3. 打开「冲突邀请｜新功能讨论」，点击「打开证据链」，展示冲突对象、候选时间和回复草稿。示例不会真实发送。
4. 从邮件页菜单再次「示例导入」。日程与邮件条数不增加，证明按邮件 ID 去重；不要把这一项描述为跨所有活动的语义去重。

预期：日历可以区分有效、取消和冲突安排；改期不覆盖原历史。

## 2:00–2:50：待办和检索来源

1. 打开「待办」，展示两封报告提醒合并为同一个事项，以及截止日信息。
2. 在邮件检索中输入「项目报告」，查看引用并返回来源邮件。
3. 打开「证据链」，选择一封示例邮件，按步骤回放。解释预置提取与真实模型调用的区别；本次示例没有 Token 或模型账单。

预期：检索返回片段及来源，执行记录能解释安排与待办从哪里产生。

## 2:50–4:00：招聘和发票

1. 从「我的工作台」进入「智能招聘」。打开林知远候选人，展示结构化简历、原 PDF、技能和经历。
2. 说明真实筛选和邀约由模型与人工审核配合；当前样例没有真实简历提取或 SMTP 投递。
3. 打开「发票助手」，查看「云服务票据待核对」。并排查看原创样本 PDF 与金额、税额、购买方等字段。明确样本不是税务凭证，字段是预置结果，未识别字段保持为空。

## 4:00–5:10：校园生活与账号边界

1. 打开 `/campus`，搜索一个示意地点，选择起终点并规划路线；展示活动、餐饮和个人计划。
2. 指出「示例目录 · 非实景导航」。真实道路、楼层、货架和菜单必须经授权核对后发布。
3. 退出登录或使用无痕窗口打开 `/campus`，公开页面可浏览；打开 `/app` 要求登录。
4. 管理页面需要演示管理员。现场若时间有限，展示自检报告中普通用户访问管理接口得到 403、越权邮箱得到 404 的记录即可。

## 5:10–6:00：交付与部署说明

展示 [云端方案](cloud-deployment.md)：同一镜像的 API / Worker / Scheduler，PostgreSQL 权威状态、Redis、RabbitMQ、私有对象存储、Caddy HTTPS。介绍从单节点 Compose 到 Kubernetes 的适用条件与上线验收步骤。

展示 `work/release-check-*/summary.json` 和 `work/demo-*/verification.json`，说明通过数、跳过数和验证范围。最终源码及构建可以打包，包内带 SHA-256 和逐文件清单。

## 演示现场恢复

| 情况 | 处理 |
| --- | --- |
| 3180 已占用 | `npm run demo -- --port 3181`，不会终止已有服务 |
| 不想重复构建 | 已有当前版本 `dist` 时使用 `npm run demo -- --no-build` |
| 样例被修改或清除 | Ctrl+C 后重新启动演示；新目录重新生成数据 |
| 真实服务不可用 | 保留原错误和任务状态，用隔离样例展示界面与业务语义；不要宣称真实调用成功 |
| 地图瓦片不加载 | 说明浏览器瓦片由外部地图提供，服务器业务自检不包含瓦片可用性；仍可展示目录、活动与列表 |
| 需要录制备用视频 | 按本脚本录屏并保留演示标记；标明录制日期与版本。本轮交付脚本和截图，视频需实际录制后再记录文件 |

展示公网二维码必须来自实际 HTTPS 域名，并在手机移动网络中试扫。本机 `127.0.0.1` 不是对外体验地址。
