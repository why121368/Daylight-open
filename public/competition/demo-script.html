0:00–0:20 首页点击「三分钟体验」 多个申请同时推进，面试时间、材料截止和临时改期散在邮件中。Daylight 把它们组织成可以追踪的下一步。
0:20–0:45 处理第一封通知，展开原邮件 10:00 面试进入日历，研究经历成为 11 月 4 日 18:00 到期的待办。通知原文随时可核对。
0:45–1:05 下一步「发现冲突」，查看黄色安排 实验室交流和已有组会重叠。系统标记冲突，生成回复草稿，让本人决定如何协调。
1:05–1:25 「面试改期」，展开已取消历史 面试从 10:00 改到 15:00。旧安排留痕，新安排关联来源。
1:25–1:40 「重复收信」 同一个邮件 ID 再出现，日程和待办数量保持相同，提取直接跳过。
1:40–2:05 「异常阻断」，展开工具执行 这里故意给出无效时间。整封校验失败，日历与待办数量保持原样，失败步骤可查看。
2:05–2:20 「修正重试」再「取消留痕」 修正后同一封邮件处理成功；后续取消仍保留通知与原因。材料待办继续由本人处理。
2:20–2:45 打开「技术与实测」，架构、流程和模型结果 API、Worker、Scheduler 按负载拆分，PostgreSQL 保存权威状态。模型回归有逐例断言、时间与 Token，失败恢复走相同工具。
2:45–3:00 修改成本计算器的邮件数和缓存比例 月费用可以按实际负载和单价估算。通过去重、上下文管理和按需加载减少重复工作。

现场准备

  1. 确认正式 HTTPS、二维码和手机网络可打开；从未登录的新窗口开始。
  2. 用 390px 与桌面窗口各走一次七步。微信检查正常浏览、折叠原文、工具记录、返回与重试；校园定位与地图外跳另行操作。
  3. 技术页保留实际环境与原始记录的链接。若网络临时受限，使用本轮截图讲解视频与本地 npm run demo -- --no-build。
  4. 真实邮箱展示由本人登录操作，避开私人正文；主动发信按已授权收件范围执行。

五项追问定位

  • 场景：日程、材料、来源和后续变更如何连起来？看步骤 1、3、7。
  • 架构：谁保存任务状态，消息丢失怎么办？看架构图、租约及幂等记录。
  • Agent：模型错了会发生什么？看整封校验失败、修正重试及模糊目标测试。
  • 工程：如何复现与回滚？看 Compose、发布 manifest、备份与镜像记录。
  • 成本：测量包含哪些环节？分别展示公开样例工具、合成邮件真实模型、真实邮箱同步三种口径。
