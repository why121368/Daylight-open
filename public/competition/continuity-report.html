1. 从实际评审路径发现问题

在正式 v18 页面依次完成面试通知、时间冲突、面试改期三步，然后打开「技术与实测」，使用浏览器返回。体验页重新挂载后固定请求第零步，已经完成的第三步和回看范围一起丢失。刷新也会重新开始。技术资料与业务体验之间的往返因此需要重复操作。

本轮让每个成功步骤有可直接打开的地址，并在同一标签页保存回看范围。电脑上点「手机接着看」，二维码直接对应当前步骤。

第三步刷新 初始化固定请求第 0 步 从地址恢复第 3 步，并定位到结果
点击导航里的「三分钟体验」 新建页面，从第 0 步开始 当前标签页恢复最后选中的步骤

二维码下载兼容处理

v19正式浏览器中，点击临时data URL下载入口后未捕获下载事件，在指定下载位置也未找到预期PNG。随后将按钮改为标准a download链接，公开体验读取随版本发布的站内PNG，同时增加长按保存说明。八个步骤文件使用qrcode算法生成，每张768×768，逐文件摘要与解码URL一起核对。

v19下载观察 · 八张静态二维码解码 · 最终标准下载链接与三尺寸弹窗。最终构建在1440/390/320px核对，下载入口为真实链接，复制、下载与手机分享均为44px，弹窗完整位于视口内。生成入口为scripts/experience-qr-assets.mjs，核验入口为scripts/verify-experience-qr.py。这些二维码由确定性编码生成，AI图片调用数保持14次。

6. 复现

node --test server/experience-progress.test.js server/experience.test.js
npm run build
npm run demo -- --no-build --port 3202

更换公开部署域名时，在构建前运行node scripts/experience-qr-assets.mjs https://你的域名，让下载PNG与新站点步骤链接一致。

打开 http://127.0.0.1:3202/experience?step=3，点击技术页、返回、刷新，再点击「手机接着看」检查地址和二维码。点击「重新体验」，刷新后应保持第零步。

另开终端执行：

node docs/competition-continuity-2026-11-04/evidence/failure-preview.mjs

打开 http://127.0.0.1:3203/experience?step=3，点击下一步，再点击重试。该入口固定绑定本机3203，代理独立样例服务的公开体验接口。

二维码验证需要Python、Pillow和zxing-cpp==3.1.1，打开保存后的PNG，使用zxingcpp.read_barcodes核对结果。最终英文图的压缩和累计用量复算入口为scripts/competition-continuity-figure.py。
